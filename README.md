# 映序 · AI 短剧工作台

独立的新工程，使用真实存储和本机 Codex。旧工程及其数据库保留，不读取、不迁移。

## 运行

要求 Node.js 24+，本机安装 Codex 并已登录 ChatGPT 账户。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:3001 。正式运行先 `npm run build`，再 `npm start`。可在 `.env.local` 设置 `CODEX_BIN` 为可执行文件完整路径；省略时从 PATH 查找。没有接入 API Key 计费回退。

`STUDIO_DATA_DIR` 可指定绝对数据目录，默认是工程下 `data`。原件、数据库、凭据均不提交到 Git。

## 数据边界

- SQLite：剧本、流程节点与依赖、每版产出、独立审核与总控验收、资产索引及来源、消息、文件元信息、流程方案、AI 会话编号和执行记录。
- 文件目录：原始文档、图片、视频原件。粘贴文字保存为 TXT；上传本身不解析。TXT/MD、DOCX 在预览或 AI 请求时读取，图片可交给模型查看。
- 页面临时状态：标签、搜索、折叠与未提交编辑。浏览器不是业务数据库。

同一个服务的电脑和手机读取相同数据。业务状态由服务端依据版本和审核记录计算；不从聊天文本猜测是否通过。

AI 每批最多执行16个子回合。用尽时将节点续跑位置（指令、发送方、审核/制作阶段与返修轮数）保存到 SQLite `node_checkpoints`，显示“等待继续”；当前批次结束后自动换批，继续原节点，再通知总控验收。批次切换不会把草稿改为通过，也不会重做已保存且正在等待审核的产出。同一节点最多4轮自动复审；同一条总控执行链累计4次退回后，重复委派也不能绕过暂停。服务崩溃、断线等结果不明的执行仍保留为暂停/失败，不自动重放可能已经执行的操作。

备份时先停止工作台与进行中的 AI 执行，再复制整个数据目录（包含 SQLite、files 与 codex-runtime 会话记录）。仅复制 SQLite 不能恢复媒体原件或模型会话。`codex-runtime/auth.json` 是指向本机 Codex 登录文件的符号链接，不应跟随链接打包凭据；换机器需要重新登录并建立链接。

网页后台使用独立的 `data/codex-runtime`（随 `STUDIO_DATA_DIR` 调整）作为 Codex 会话和状态目录，后台讨论不进入桌面任务列表。应用不读取登录令牌内容，交由 Codex 通过本机符号链接读取已有登录。旧会话在下次续聊前按已保存编号复制到独立目录，保留原记录，不导入其他桌面聊天。升级前正在执行的会话仍按原方式完成并归档。创建符号链接需要操作系统支持；失败时报告错误，不回退到共享会话目录。

## 代码职责

聊天支持直接描述图片需求，使用本机 Codex 的原生出图能力。系统建立图片任务、保存真实文件并自动送节点独立审核，总控查看图片后作最终验收。聊天显示生成中/失败/待审核/可使用状态，缩略图可放大并下载；生成记录、提示词、参考图编号与产出版本持久保存。需要当前登录账户和 Codex 版本支持图片生成；失败不自动反复重试，也不切换到其他付费服务。视频仍由人工制作和上传。

| 目录            | 职责                                   |
| --------------- | -------------------------------------- |
| src/domain      | 纯业务类型、结构、依赖与状态规则       |
| src/server      | SQLite、文件存储、正式命令和读取视图   |
| src/server/ai   | Codex 通信隔离、执行与身份权限、提示词 |
| src/app/api     | 参数验证、同源写入、后台执行入口       |
| src/application | 页面操作与 HTTP 同步                   |
| src/features    | 导入、讨论、流程、任务、资产界面       |
| src/shared      | 弹窗、Markdown、文件预览、移动端布局   |
| src/mocks       | 测试夹具，不注入正式数据库             |

当前实现及限制见 [实施边界](docs/实施边界.md)，产品基线见 [产品需求](docs/产品需求.md)，存储结构见 [存储与执行](docs/存储与执行.md)。

```sh
npm test
npm run typecheck
npm run build
```
