# 短剧工作台核心底座 · 设计 v0.1

## 1. 目标与边界

用户与总控讨论，专业 AI 按节点参与双向协商。制作流程随故事与项目变化；资产存储、审核、版本引用、事项记录、消息投递的核心规则固定。

建设顺序：核心底座 → 个人制作 → 团队协作。当前不建立岗位模板表，不强制分成永久的 dev/生产 AI，不建设 Skill 市场，不预设一条制作流水线。

## 2. 数据独立，总览聚合

Project 仅保存名称、说明、目标。故事大纲与剧本以 Document 及修订保存；Workflow 保存讨论后确定的流程；Node 保存节点状态与依赖；WorkItem 保存实际事项。项目总览从接口聚合，不保存重复的当前流程、当前阶段、完成率。

支持同一时间多个节点进行。新建项目只初始化未发布的讨论容器、总控节点、未配置执行器的总控 AI 与空聊天，不自动发布制作流程。讨论阶段从独立的总控聊天入口沟通，制作流程页保持空白；确认制作方案后，由总控通过接口补充节点并发布流程，才展示正式流程图。讨论容器用于维持节点与 AI/会话归属，不代表已确定的制作流程。已发布流程允许通过接口继续追加节点与分组，无需提前设计全剧。追加保留原节点、会话、成果与普通节点依赖；重排或替换已有结构仍需要显式处理，不能悄悄删除活跃节点。

流程可采用总分总结构：全剧规划与共用资产 → 分集/章节制作 → 全剧汇总与交付。WorkflowSection 保存分组与分集顺序，NodeSection 保存节点归属；不把分集数量写死在界面。每个制作单元保存独立节点、事项、AI 和会话，重复制作通过新增单元表达，不给依赖图添加回环。新单元复用明确版本的基础资产，完成后进入全剧汇总。扩展接口原子创建单元，并把其出口接入汇总前置；汇总已经开始时禁止静默追加。

前期、季、分集和归档均可逐步定义。分集允许先存名称、暂不建制作步骤；后续用节点接口逐个补充。同批创建分集步骤时可显式指定入口依赖，不提供时沿用当前共用前期的出口，没有前期则不添加依赖。归档后建时连接当前制作出口；后续扩展仅为未开始的归档补充必要门槛并记录审计，不改写普通节点的历史依赖。已有归档节点或事项开始后禁止追加制作内容；空分集属于尚未规划完成，不能被当作已完成绕过归档检查。

总图采用纵向连线：总控协调 → 实际共用节点 → 可选季 → 分集/章节 → 归档。WorkflowSeason 独立保存季的说明和顺序，SectionSeason 记录制作单元归属；不建季时直接显示分集。界面将各集的内部节点归并为可点击入口，点击后进入本集制作流程。总控打开项目基本信息、故事文稿和讨论。总图的季归属线和总控导航线是展示关系，不新增执行门槛；真实依赖仍由 NodeDependency 保存。空季可以保留规划，但不假装已完成或接入归档审核。

## 3. 流程节点与 AI 身份

项目 → 流程 → 节点 → 多个 AI。AI 保存名称、定位、指令、提供方、模型、允许工具与 Skills。总控也是一个 AI 身份，归属协调节点；不引入岗位模板。

AI 身份不是 Session。一个 AI 可以有多个 Session；每个 Session 有内部 ID、外部 session/thread ID、提供方、状态及前继会话。每次 Run 保存当时配置和输入版本快照。

## 4. 讨论与核心重点

用户只能通过总控沟通。子 AI 的消息可查看、引用到总控会话；接口层拒绝人直接写入子 AI 会话。未来团队阶段改变通信权限策略，而不是重建会话模型。

Discussion Highlight 独立存储目标、提议、已确认结论、理由、未解决问题、下一步、作废信息。绑定节点和可选源消息，保留修改/替代链。提议不自动变成结论。回看先展示当前有效重点，按需打开原始讨论。

## 5. 资产库

资产包括文稿、图片、音频、视频等；有项目内稳定编号。Asset 保存说明与可查询属性；Version 保存具体不可变内容及状态；File 保存文件键、名称、MIME、尺寸/时长等可扩展元信息。

形态与版本分开：20岁和40岁男主可同时存在，是同一角色下不同资产/形态；同一形态的修订才是版本。服装、年龄、姿态、角色标识等使用显式属性，不靠接口识图猜测。

单项基础资产先定稿。场景分析识别所需素材并检索复用，缺项/组合需求提交总控，总控协调生成，审核后登记。组合资产属于项目，可供多场景重复使用，不是场景一次性文件。

来源是 DAG：组合版本可以有多个来源版本。每条来源关系绑定具体版本。新正式版本不自动替换旧任务的输入。使用关系记录事项、节点对资产版本的引用；查询下游影响再决定是否重做。

草稿/候选/定稿分开。审批记录明确批准范围；候选通过审批并完成文件归档后才发布。用户不必逐次介入所有审核，审核主体与权限后续可配置。

## 6. 标准接口

API 只按参数执行：按 ID 查询、按属性筛选、取版本、来源/使用查询、提交审核与发布。查不到返回空列表或 404；多条返回列表；错误参数 400。不得默默放宽条件或挑一个最像的资产。

输入经 schema 验证，外键与项目范围检查。统一 {data, error, requestId}。文件通过受控文件接口提供，不由 AI 输入任意磁盘路径。

## 7. 事项与执行

事项有目标、负责人/执行者标识、节点、输入版本、交付要求、依赖、阻塞和状态。完成依赖后才能执行；支持退回、取消和并行。

运行计划、实际提交、运行中、完成、审核与发布分别记录。运行具有请求幂等键、配置快照和结果。接口不能假装发起了外部任务。未配置执行器明确 blocked。

下一阶段的执行器会负责消息队列、模型适配、工具调用、预算及重试限制、外部状态核对；程序重启不盲目重发未知状态的付费任务。

## 8. 上下文和 Skills

按事项构建目标、已确认重点、指定输入资产、身份配置和可用 Skills。不会给子 AI 所有项目聊天或默认全部废稿。可追溯本次实际输入。

Skill 注册表保存 ID、版本、说明、能力类别；AI 绑定允许列表。没有市场/下载安装功能。分镜 AI 是否允许生图由明确能力配置决定；真实执行器上线后还须在执行边界强制检查，不能只靠提示词。

## 9. 网页

导航从折叠的项目文件夹开始。展开项目后有三个入口：**总控聊天**、**制作流程**、**故事资产库**，不再另设总览、沟通汇总、文稿、执行记录页面。手机使用可收起的项目目录。

制作流程页仅展示当前已发布且含实际制作节点的流程图，不展示草案图或孤立总控节点图。未发布阶段保持空白，不在流程页放置说明、聊天或资料入口。总控聊天独立成页，点击导航直接进入对话，可查看历史聊天或打开资料。按真实前置依赖从上往下自动排布分支与汇合；不虚构无依赖节点的连线。直接在面板展示，移除缩放、适配和尺寸控制；内容随页面自然展开。点击节点打开详情，查看目标、输入、交付、状态、前置依赖、讨论重点、AI 与事项；下方可进入已有聊天或添加聊天。用户仍只向总控发言，子 AI 的消息可查看并引用到总控。节点详情和节点聊天作为独立内部页签打开。顶部页签支持切换、关闭及键盘导航，相同项目/资源重复打开会复用页签；不同项目或会话相互隔离。非活动页面保留挂载但隐藏，切换时保留未发消息、资产分类及页面滚动位置；关闭页签释放该页临时状态，历史消息仍由数据库保存。页签仅属于本次浏览会话，不存入项目业务表。

故事资产库首先展示分类文件夹：故事文稿、人物、场景、道具与服装、组合资产、制作资料、图片、音频、视频；讨论与决策、任务与执行放在独立的项目记录分组。打开分类后只列出该类记录，搜索也限定在当前分类，不提供默认混排的全部列表。点击记录查看完整内容；资产展示属性、批准范围、版本、来源和实际文件。搜索按存储内容匹配，不调用 AI 识别；聚合视图不建立重复业务存储。

网页不提供流程、节点、节点 AI 和工作事项的手工搭建入口。这些结构由总控及子 AI 通过标准接口登记和推进；用户在网页查看、讨论及审核。流程生成接口继续保留，未配置执行器时不显示虚假的生成进度。

提供显式运行的完整故事样例《青禾剑录》，可整理为全剧规划、三集独立制作、全剧汇总；三集结构共 36 个节点。演示文字规范保存为实际文件并标明批准范围；青年/中年人物形态共存，组合规范关联来源版本。图像、音频和视频保持待制作需求，节点不伪装为执行完成。重复创建不会覆盖已有项目数据。使用具体故事作为项目展示时，项目名称与日常说明不带样例标签。旧验收项目可归档移出日常目录，保留原数据并可恢复。

## 10. 存储与后续扩展

制作偏好入口为标题旁的小加号：在标题下就地展开类别选项，勾选或取消即时更新下方具体要求，不使用遮罩、浮动定位或确认按钮。小加号再次点击可收起类别区，保留选择。每类具体选项使用直接可见的单选卡片，需要时填写自定义内容；移除类别清除该类内容。当前五类目录为画面风格、制作范围、改编要求、单集时长、画幅。类别与选项存入后端数据库（含顺序、启用状态和自定义输入说明），GET story-preferences 返回可用目录；前端不写死选项。初始化种子只运行一次，不覆盖后续配置。迁移 9 停用发布平台与 discuss 选项；勾选类别不自动选中具体值，未选具体值的类别不进入聊天消息。总控默认指令要求先阅读故事、整理已知条件并确认基本制作信息，关键方向确认后再开展制作；现有总控保留原指令并追加该要求，历史聊天不改写。

用户的选择和自由想法仅在当前表单中暂存，作为总控聊天输入，不建立 StoryBrief 或其他独立偏好记录。未选类别不提交，取消选择清除该类内容。原始故事保存成功后，网页调用独立讨论接口，将这些输入与故事引用组织为一条用户消息并直接打开独立聊天视图，底部入口文案为「开始讨论」。聊天提供返回节点资料入口，不先展示节点信息列表。首次消息包含原始文件的项目内 API 路径，不复制故事正文。聊天界面隐藏原文路径及其标签，仅展示原始文件名，点击文件名打开弹窗预览，不新增内部页签。发送给 AI 的消息仍保留路径，历史消息不改写。普通粘贴内容也是持久化的 UTF-8 .txt 文件；原文页从文件接口读取 TXT/Markdown 并以纯文本呈现，保留换行、空格，不执行 HTML 或渲染 Markdown。上传的文本可由用户显式选择显示编码，读取不改写原文件，不参与故事分析。其他原始格式保留下载入口。原文浏览链接支持独立打开或刷新，按项目与故事 ID 校验范围。只有消息历史持久化这些意向，具体制作信息由总控在讨论后决定通过哪些接口登记。StoryDiscussion 仅记录故事与消息关系以支持重试。旧偏好表保留历史数据，不再读写或显示为故事设定；已有聊天不改写。

没有模型执行器时，只能显示消息已保存、分析尚未开始；交接失败不回滚故事，表单保留未发消息内容供重试。关闭窗口不会保存未发送的偏好草稿。导入与交接均不自动创建制作要求、讨论结论或制作流程。

原始故事以 StorySource 独立保存，与后续大纲、改编剧本等 Document 分开。网页新建项目默认上传文件，入口依次为上传文件、粘贴文本、剧本库。上传区支持一次点击多选或拖入多个文档、图片，已选列表显示文件名、大小，允许继续追加、逐个移除；同名、同大小、同修改时间的重复选择在当前列表中去重；移除仅取消本次选择，不删除磁盘原文件。剧本库打开独立建设中弹窗，不改变已选来源或表单内容。文件支持 TXT、Markdown、Word、PDF、PNG、JPG/JPEG、WebP、GIF；图片也支持点击或拖拽上传、追加和移除；一次最多 20 个文件，单文件上限 20 MB，合计上限 50 MB。图片原样保存，不 OCR、不转文本、不进行内容分析；聊天只显示图片文件名与图片图标，点击在同一预览弹窗中显示原图，不创建页签。图片预览使用独立受保护的同源图片接口，按文件头返回实际 PNG/JPEG/WebP/GIF 类型，兼容后缀名与实际格式不同的原文件，不再通过浏览器临时 Blob 地址显示。读取时只核对格式签名，不解码或改写图片。图片按可用宽度等比例显示，长图在弹窗内上下滚动，不按视口高度压缩整图。已有项目可从总控节点或故事文稿分类追加导入。粘贴文本原样生成 UTF-8 文件，上传文件保留原始字节；数据库保存稳定 ID、所属项目、来源方式、名称、文件键、大小、摘要和时间。先写入实际文件，再以事务提交项目初始化和来源记录，失败回滚并清理本次文件；同一导入键重试不会重复创建项目或故事。存储层不识别编码、不提取正文、不生成内容预览；所有来源均能按 ID 查询元信息并下载原始文件，解析动作交给后续 AI。导入不生成 AI 消息或制作步骤。

SQLite 保存结构化信息、文本、关系和审计；data/files 保存原文件。数据库与文件共同备份，不进入 Git。运行服务与网页请求分离是下一阶段重点。

团队扩展预留 creator/actor/owner/reviewer 标识，届时增加成员、权限与并发编辑控制。当前本地模式不宣称具备团队安全能力。

## 11. 技术决策

TypeScript + Next.js + React + SQLite（node:sqlite）+ Zod。先减少安装和运维负担，业务规则置于独立服务而非页面。后续 PostgreSQL、对象存储和独立 worker 通过适配及迁移引入。

参考：https://nextjs.org/docs/app/getting-started/route-handlers 、https://nodejs.org/api/sqlite.html 。

多文件提交作为一批保存：一个新项目、多个独立 StorySource，批次键和有序来源关系负责整批重试。失败事务回滚并清理本批已写文件；重试不产生重复项目或来源。共有故事名称用于项目名，多份来源各自保留原始文件名与标题。整批保存后只生成一条总控消息，携带全部原文件路径，制作偏好和想法只写入这条消息。StoryDiscussion 允许一条消息关联多个来源并保存顺序；workspace 聚合 attachments 数组，不复制消息。聊天按附件逐个显示文件名、点击分别预览。已交接文件集合或顺序改变时返回冲突，避免遗漏文件或混合历史交接。原单文件导入接口及旧聊天仍兼容。

## 12. AI 提示词编辑与聊天追溯

聊天标题区与节点 AI 详情提供「AI 设置」，查看、修改并保存当前 AI 的提示词；当前版本可编辑，历史版本只读，配置仅影响该项目的该 AI，不修改默认模板或其他项目。保存后继续当前聊天也会对后续消息生效，不强制新建会话。

agents.instructions/config_version 保留当前配置，agent_prompt_versions 保存不可变提示词版本、留档时间及来源。创建 AI 时原子保存初版；修改时校验 expectedVersion，内容未变不新增版本，相同提交重试不重复保存。并发编辑冲突返回 409，前端保留草稿并显示最新版本供对照，由用户明确选择基于最新版本继续。

message_prompt_versions 按消息保存关联版本；发送用户消息与版本引用在同一事务完成。聊天里的「提示词 vN」读取该条消息关联的历史原文，旧消息不因当前配置修改而变化。普通发送和故事首次交接共用这套记录。现阶段模型执行器未接入，记录只代表提交消息时的提示词配置，不宣称模型已经使用；后续执行器需另行记录实际调用输入快照。

升级仅为现有 AI 留存当前配置，origin=baseline，不为旧消息倒填推测版本。旧消息显示「提示词未留档」。历史版本、消息关联不允许更新或删除；接口校验项目与 AI/消息归属，数据库约束消息关联必须属于会话的同一个 AI。

故事资产库新增独立「提示词」分类，按项目聚合已有 AI 的非空提示词，展示 AI 名称、当前版本和关联节点，支持分类内搜索。每个 AI 展示一条当前记录，点击复用 AI 提示词编辑与历史版本界面；直接引用 agents 和 agent_prompt_versions，不复制到另一份资产表。保存后刷新项目聚合视图，使设置和资产库一致。

AI 设置的提示词视图右侧增加「提示词库」入口，打开独立建设中弹窗。关闭或按 Escape 只关闭库弹窗，保留底层编辑草稿、当前版本和历史选择；不读取或填入模板。剧本库与提示词库共用建设中弹窗组件，保持一致的样式和焦点行为。

提示词「历史版本」使用叠加的独立只读弹窗，底层提示词编辑器保持挂载。叉号、Escape 或点击上层背景只关闭历史弹窗，焦点回到历史入口，保留底层未保存编辑。历史读取独立管理加载和错误，关闭时取消请求，不影响当前编辑器。

总控默认提示词采用按需阅读策略：先看文件元信息与既有分析，根据讨论目标与原作分析子 AI 协商，由子 AI 自主选择读取位置、范围、顺序和继续阅读的时机，不固定章节数、字数或分章格式。阶段分析保存覆盖范围、原文位置、已知/推测/未知，优先复用并按需核实；不将局部阅读表述成全书理解。工具或子 AI 未接入时明确说明，不虚构执行。迁移 13 将此规则作为新版本追加到现有总控，保留自定义内容、旧版本和消息关联，不修改子 AI；迁移只执行一次，不覆盖用户后续调整。首次故事交接消息也改为先了解资料、按需分析，不要求先通读所有文件。此变更仅更新提示词，尚未实现阅读或子 AI 执行工具。

总控提示词采用带标题与条目的结构：身份定位、核心目标、职责与当前任务、协作与沟通要求、原作阅读策略、成果保存与引用要求、执行边界；存在自定义内容时增加项目补充要求。新项目使用此模板，迁移 14 为已有总控建立新版本，仅替换完全匹配的历史内置段落，其他内容原样保留在补充要求中；保留旧版本、消息引用和子 AI 配置，重启不反复重写用户后续编辑。

## 13. 总控与子 AI 的提示词及讨论格式

总控提示词内定义三类可读格式：A 为子 AI 身份配置（身份、目标、职责边界、工作要求、实际工具与 Skills、反馈、成果保存）；B 为具体任务或讨论消息（关联信息、目标、已确认背景、输入引用、任务、要求、交付审核、待讨论问题）；C 为子 AI 回复（关联与状态、理解与结果、覆盖范围与来源、成果引用、问题建议、下一步）。总控按节点填写具体内容，通过已有 AI 配置接口保存身份提示词；本次任务属于会话，不反复改写长期身份。

首次交接和重大目标变更说明完整上下文，短讨论仅补充相关字段；缺项写待确认，不适用项可省略，不虚构编号。资料按真实编号、版本、文件地址引用，长篇原作按需读取，不固定阅读章节数。子 AI 可提问、反馈冲突和提出替代建议；影响结果的问题先协商，不受影响且已授权的工作可继续。关键结论通过实际接口独立保存，候选成果交总控组织审核。对话状态不等于已修改数据库，提示词也不授予工具权限。

新总控默认包含该规范。迁移 15 为已有总控追加规范并保存新版本，保留原有自定义内容、历史版本、消息引用和已有子 AI 配置；迁移只运行一次，保留后续用户修改。规范要求总控在创建或调整子 AI 时写入相应要求，不直接批量改写各专业 AI。当前仅定义提示词约定，尚未接入子 AI 消息执行器，不新增消息投递或宣称已执行协作。

## 14. 总控自主接续与交接

总控可以根据阶段与上下文负担自主判断接续时机，常规接续只告知用户，无需重新审批或重复收集制作意向。优先以同一总控身份创建带 predecessorId 的新会话，继续项目；不新建重复项目或互不关联的总控身份。

提示词规定先保存有效结论和独立交接记录，再向新会话传递交接引用、简要目标及首项任务。交接格式包括关联编号、原因目标、已确认约束、进度成果、子 AI 会话、在途操作、未决问题、接手顺序及回查入口。交接是快照，实时状态仍查询业务记录；未知执行状态先核实，避免重复生成或发布。新总控核对资料并确认接手后，旧总控停止推进已交接事项；切换期间新增意见与结果需补交并确认接收。失败时保留原会话承接工作，旧消息与配置可回溯。

新总控默认包含该规范，迁移 16 为现有总控追加为新版本，保留自定义内容、旧版本、消息关联及子 AI 配置；后续重启不重新注入。此次仅更新提示词约定，现有接口能登记前继会话，但自动启动模型、交接消息投递、接手状态与切换路由仍需执行器实现，不能把空会话创建视为自动交接已完成。

## 15. 系统配置与用户配置分层

AI 设置分为「内容提示词」「系统规则 · 只读」「工具与 Skill」。内容提示词允许编辑或清空；系统工作规则、必备工具和必备 Skill 由平台维护，不提供用户修改接口。必备能力显示平台基础接口是否具备，明确区分尚未接入的自动协作能力；没有执行器时不宣称模型已获得可执行工具。暂未内置必备 Skill，不虚构已安装项目。

system_ai_policies 按显式节点类型保存不可变的规则版本、必备工具与 Skill。现阶段仅有 coordinator/work 两类明确节点类型，先提供总控规则和工作节点共用规则，不根据名称、提示词猜测专业节点类别；原作分析、分镜等更细的系统能力模板随后续明确节点分类扩展。平台发布新版本才能升级系统规则，用户编辑接口不能替换政策编号、规则文本、必备能力或允许范围。

agents.instructions 及 agent_prompt_versions.instructions 在分层后只保存用户内容；旧版本仍保持历史完整原文，不倒填推测的分层信息。agent_config_layers 按 AI 配置版本关联系统规则版本，并保存用户选配工具、Skill 内容和版本、允许选择的工具范围。新建 AI 自动关联节点对应的系统规则，用户传入的工具属于扩展能力；system. 命名空间禁止由创建请求声明。内容提示词不能作为工具授权依据，也不能修改系统规则。

用户可在此 AI 已配置的扩展能力范围内启用、取消工具，并选择依赖匹配的已登记 Skill；初始允许范围来自节点 AI 创建时的明确工具配置，后续用户编辑不能扩大范围，未来由受控节点配置升级它。当前暂无扩展能力的 AI 显示为空，不放开整个 Skill 注册库。取消工具时必须同步取消依赖的选配 Skill；前端联动，后端再次校验。Skill 定义沿用独立注册的版本，新版使用新 ID，不修改已有版本或复制成系统规则。

PATCH prompt 接口严格只接受 expectedVersion、instructions、optionalTools、optionalSkillIds，拒绝其他字段，保持项目归属与乐观并发控制。工具和 Skill 的调整同样产生新的配置版本，旧绑定 Skill 接口复用该保存流程，避免绕过留档。配置与 Skill 绑定原子保存；系统规则及配置快照由数据库禁止更新、删除。资产库继续从现有配置聚合，未填自定义内容的 AI 也可打开设置。

消息仍关联 AI 配置版本，由其查到当时的两层配置及能力；历史窗口分别展示内容、系统规则与选配。事项上下文和运行配置快照增加完整 prompt 分层对象，后续执行器必须按系统规则、用户内容、任务资料的来源分别装配，不能把用户内容当成平台规则，也不得仅取 agents.instructions 作为完整配置。运行仍明确未接入。

迁移 17 为所有已有 AI 新增分层配置版本。总控仅拆出完全匹配的内置规则，保留原有身份目标模板及自定义内容；无法可靠识别的文字留在用户内容中，不自动删除。子 AI 自定义内容保持原样，关联工作节点共用规则。全部历史提示词、消息与会话保持原样，已有用户工具和 Skill 选择保留；迁移仅执行一次。

## 16. 当前前期流程收敛

当前按故事入库 → 原作初步分析 → 总控确认需求 → 编剧设计并确认改编框架 → 编剧直接拆分和保存原文引用实施，具体契约见 [前期流程接口](前期流程接口.md)。编剧可内部逐层分工，不经总控搬运全量文案；总控接收摘要、编号和需要协调的问题。流程发布后显示公共故事资料分支与空剧集入口，暂不展开集内制作。

上述接口是确定性的存储与查询，尚未接入模型执行器。概况、需求、框架、知识提议及审核分别持久化；项目总览继续聚合生成。迁移 18 增加显式专业节点配置与稳定剧集编号，保留旧项目、消息、配置和素材。

本次简化替代此前的剧本库、提示词库“建设中”页面规划：暂时移除这些未实现入口，资产库只显示有内容的分类；实际提示词配置、历史和已有资料仍保留。
