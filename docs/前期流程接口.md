# 故事入库到分集入口

当前实现止于原文分配，不生成具体剧本、分镜或集内制作节点。下列接口是确定性存储与查询接口；AI 执行器尚未接入，创建会话、登记委派、保存消息均不代表模型已经运行。

## 流程与职责

1. 用户上传故事或粘贴文本，原件独立保存；意向只进入总控聊天，不在上传时生成需求记录。
2. 总控调用 `POST /projects/:p/preparation`，传入 `coordinatorSessionId`，登记原作分析与编剧节点、各自 AI 和会话。通过 workspace 查询节点对应的会话 ID。此时流程仍为草稿，页面不显示流程图。
3. 原作分析 AI 按需读取并提交 `overview`。说明已读范围、原文依据、已知及未确定内容；不要求固定章节数量，不推断全书情节，也不强制存在主角或男女主。总控检查后确认。
4. 总控与用户讨论集数、时长、选材范围、删减和约束，保存 `requirements`，引用已确认概况。用户确认消息作为确认依据。
5. 编剧依据已确认需求提交 `framework`：选材、粗略结构、跳过内容的衔接和改编方向，不写具体内容。总控组织用户确认后发布流程图。
6. 编剧调用 episodes 接口直接创建空剧集/篇章入口，关联原始资料与公共资产版本。返回简短清单供总控查看；不经过总控转存整批正文，不创建集内制作步骤。

编剧可自行登记下级 AI，逐层分工和讨论。常规子任务由编剧汇总；影响已确认范围或需用户决策的问题再报总控。用户只能向总控发言，其他讨论可查看和引用。

## 调用约定

所有地址以 `/api/v1` 为前缀，`:p` 为项目 UUID。响应沿用 `{ data, error, requestId }`。所有引用限定在当前项目；session ID 必须属于相应节点且处于打开状态。确定性接口校验归属、类型、状态与字段，不替 AI 判断原文含义或某条用户消息是否语义上同意方案。接入执行器时还需把运行身份绑定到对应会话，不能把调用者自报 session ID 当成独立身份认证。

### 分别保存和确认前期成果

`POST /projects/:p/preparation-records`：

```json
{
  "kind": "framework",
  "authorSessionId": "编剧会话 UUID",
  "basisId": "已确认需求 UUID",
  "content": {
    "title": "改编框架",
    "summary": "本次范围和结构摘要",
    "details": "选材、重组与衔接思路",
    "scope": "明确的原作范围",
    "constraints": [],
    "unresolved": [],
    "sources": []
  }
}
```

`kind` 为 `overview | requirements | framework`。概况由分析 AI 保存，需求由总控保存，框架由编剧保存。需求引用概况，框架引用需求。可记录 `episodeCount`、`minutesPerEpisode`，允许在讨论中逐步明确。修订传 `previousId`，创建不可变新版本，旧版保留；一类成果只有一条修订链。

`POST /projects/:p/preparation-records/:id/review` 传 `coordinatorSessionId`、`decision`（`confirmed | changes_requested`）、`reason`。确认需求或框架另传 `userMessageId`，必须是当前总控身份下的真实用户消息。确认后的内容不能直接覆盖；依赖新版前先确认新版。

`GET /projects/:p/preparation-records` 返回元信息与摘要；`GET .../:id` 按需读取完整成果。项目总览由这些记录聚合，不在 projects 上存重复的当前阶段。

### 原始资料引用与分段读取

引用形式：`{ storyId, locator, startByte?, endByte?, encoding? }`。`locator` 是调用者明确给出的定位说明；系统不猜章节。文本精确范围需同时提供起始字节、结束字节和编码；范围采用 **左闭右开**，不是字符索引。支持 TXT/Markdown 的 `utf-8 | gb18030`。PDF、图片等引用整个原件并说明位置，不自动解析。

`GET /projects/:p/stories/:id/range?startByte=0&endByte=900000&encoding=utf-8` 按明确范围读取。单次最多返回 512 KiB，必要时在字符边界结束，返回 `endByte`、`requestedEndByte`、`hasMore`、`sourceSha256` 和 `text`。后续从返回的 `endByte` 继续；这个分页限制不决定 AI 的阅读范围或章节策略。

原件仅保存一份，剧集的原文归位通过持久化有序引用实现；点击可查看原件或指定片段，不改写、概括替换或重复复制原始文本。导入与元信息读取仍不解析内容。

### 编剧直接建立剧集

`POST /projects/:p/episodes`：

```json
{
  "writerSessionId": "编剧会话 UUID",
  "frameworkId": "已确认框架 UUID",
  "requestKey": "本批请求 UUID",
  "units": [
    {
      "name": "第一集",
      "kind": "episode",
      "summary": "本集覆盖内容简述",
      "sources": [{ "storyId": "原件 UUID", "locator": "明确的原文位置" }],
      "assetVersionIds": []
    }
  ]
}
```

`kind` 可为 `chapter`。每批 1–100 个入口，全部成功或全部回滚；同请求键相同内容返回原结果，改变内容则冲突。可分批追加，避免一次装载所有内容。响应只包含入口 ID、稳定编号、名称、摘要和查询地址。

- `GET /projects/:p/episodes/:idOrCode`：查本集元信息、原文引用、公共资产引用。
- `GET /projects/:p/episodes?around=E0003&before=2&after=3`：按当前展示顺序查相邻多集。每个方向可取 0–100 个。
- 列表支持 `workflowId`、`offset`、`limit`；不做语义检索。
- `PATCH /projects/:p/episodes/order`：传 `writerSessionId` 和本流程全部 `episodeIds` 调整顺序，不改变稳定编号、ID 或原文。

`E0001` 等是项目内稳定查询编号，重排后不重新编号；`number` 是当前展示顺序。旧项目既有剧集也分配稳定编号，原来的流程与资料保留。

### 编剧内部委派与讨论

`POST /projects/:p/writer-delegations`：传 `parentSessionId`、`requestKey`、`name`、`objective`，可带 `sourceIds`、`recordIds`、`episodeIds`。创建当前编剧节点下的独立 AI、会话、上下级关系与任务消息，返回 `child_session_id` 等引用。子 AI 可继续委派。请求键保证重试不重复登记。

`POST /projects/:p/sessions/:toSessionId/agent-messages`：传 `fromSessionId`、`content`，仅允许已登记的直接上下级相互讨论。保存到接收会话并关联该会话提交时的配置版本。响应 `delivery=stored`、`execution=not_configured`，不伪装模型回复。需要向总控报告时由其直接子 AI 汇总，减少重复上下文。

### 逐步完善公共故事资料

`POST /projects/:p/knowledge`：传 `authorSessionId` 和 `payload`（`summary`、`entities`、`relations`）。实体包含 `code`、`name`、`kind`（person/concept/setting）、`role?`、`description`、`sources`、`assetVersionIds`、`expectedRevision`；关系包含自身稳定 `code`、实体 `from/to`、`label`、`period`、`description`、`sources`、`expectedRevision`。

`POST /projects/:p/knowledge/:proposalId/review` 由总控传 `coordinatorSessionId`、`decision`、`reason`。确认后原子更新公共图谱；同实体/关系修订须提供当前版本，冲突不会覆盖较新结果。每份提议和审核保留。不同关系阶段使用不同关系 code，保留早期和后期，而非相互覆盖。

`GET /projects/:p/knowledge` 返回已确认实体、关系及提议摘要；`GET .../:proposalId` 查提议详情。画像文件仍在公共资产库；故事资料引用版本并展示其状态，剧集只接受已定稿版本。人物的不同年龄形态使用不同资产变体。

## 页面与迁移

故事资料从总控下拉一条导航线，也可在故事资产库打开；它不是执行依赖。图中人物、概念、关系可点击，前期概况、需求、框架分别查看。剧集入口显示原始文案、关联资产、相邻与其他剧集导航，内层流程留空。

暂时移除「剧本库／提示词库建设中」入口与没有资料的分类，不删除原件、资产、聊天或历史。系统规则继续只读，用户内容提示词仍可编辑。

迁移 18 增加前期成果、图谱、委派与剧集引用表；总控追加配置版本，绑定新的系统规则。只替换完全匹配的旧内置内容，保留用户自定义内容；旧子 AI 配置、旧消息和历史版本不变。新专业节点通过受控 `node_ai_profiles` 显式绑定，不根据名称猜职责。
