# 存储与执行

## 表的职责

| 数据                                       | 存储                 |
| ------------------------------------------ | -------------------- |
| 剧本身份及变更版本                         | projects             |
| 剧集目录                                   | episodes             |
| 任务定义、前置关系                         | tasks / dependencies |
| 产出版本及引用资产                         | outputs              |
| 内容审核、总控验收，含版本/决定人/理由     | reviews              |
| 任务操作轨迹                               | events               |
| 已验收资产索引及来源                       | assets               |
| 群内消息、发送身份、关联节点               | messages             |
| 原件元信息及校验值、版本附件绑定           | files / output_files |
| 流程方案与用户确认消息                     | plans                |
| 节点/身份对应的模型会话                    | sessions             |
| 每轮执行、父子执行、提示词快照、状态与错误 | runs                 |
| 写入工具的调用回执                         | tool_receipts        |
| 导入重试去重                               | import_requests      |

页面项目总览、可开展任务、验收状态、文件组均由这些独立记录聚合。没有把整个前端对象直接存成一个大 JSON。产出中的引用数组、方案正文属于有界文档内容，可使用 JSON；文件二进制不放数据库。

## 审核边界

1. 制作 AI 只能提交所指派任务。
2. 独立审核 AI 只能审核该任务当前版本，不能验收或写制作稿。
3. 总控进行最终验收/退回；人工介入以 human 身份记录，不伪装总控。
4. 后端检查前置是否正式验收、当前版本、启用状态、内部审核、媒体原件及引用资产。
5. 任一产出文本/附件变更创建新版本，旧审核不继承。普通已验收产出禁止直接修改；整体剧本和分集分镜可以提交增补版本，经再次审核、验收展开新分支，不能覆盖已开展的分支。
6. 禁用审核留下操作记录，不能直接批准内容；禁用执行不清除已通过产出，不人为阻塞不相依赖的分支。

## 执行边界

使用 Codex app-server 的 stdio 通信，动态工具绑定项目/身份/节点。客户端不能提供审核身份。模型不能传另一个项目编号绕过范围。继承的外部 MCP、插件和通用本机执行工具关闭。模型只通过工作台工具操作业务数据。

参考：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。

SQLite 事务负责业务写入原子性，前端携带项目及产出版本检测并发。媒体先写随机编号文件，业务失败则清理未引用上传；服务被强制结束时可能遗留未引用文件，当前不会自动删除任何已记录文件。

执行过程存储 thread/turn 编号、各身份会话和提示词快照。重启后失去执行进程的任务标记中断，保留已完成操作，等待用户继续。后台长任务依赖常驻 Node 服务，不适合直接部署到有短执行时限的无服务器函数。

## 2026-09-19 系统转交与增量流程

数据库版本 5：新增 output_structures（与产出同版本的剧集/镜头拆分）、episode_focus（分集关键镜头）、node_jobs（任务状态与群聊状态气泡）、node_questions（问题的审核、转交和答复）、raw_events（实际输入、回复、工具调用/结果）、session_toolsets（会话工具签名）、legacy_scaffolding（旧空占位标记）。原始记录按会话分页，每页 50 条，关联实际执行及其 thread/turn、提示词快照。

节点审核各自有独立会话；共用审核模板不代表共用上下文。系统驱动退回重做和问题门控。审核停用保留跳过记录，总控仍需验收。重启/达到复审上限保留待办，不自动重放副作用。更新工具清单时保留历史会话记录，为下一次执行建立匹配新工具的模型线程。

只有验收事务可以从结构化产出建立剧集/镜头节点。部分分镜标记 complete=false，整集合成会等待完整分镜，避免把一个关键镜头误认为整集完成。旧版本空占位隐藏且禁止执行；实际产出、附件、审核和聊天保留。

## 2026-09-19 长任务交接修复

模型的 turn/completed 不等于工作台的子任务完成。总控轮次提前结束时，项目执行仍保持运行，等待已接收的工具处理完毕，再由系统续接总控处理保存的交付或失败。续接使用独立执行记录与真实系统身份，不新增伪造用户确认，不重跑已完成制作。已有卡住的 submitted 任务可通过幂等的 queueDelivery 恢复交接。

复现测试覆盖子任务晚于总控结束、晚到失败、等待期间互斥、系统恢复幂等与身份。事件协议参考 [OpenAI App Server 文档](https://developers.openai.com/zh-Hans/docs/app-server)。

## 2026-09-19 原作定向补读

已验收的原作理解允许由总控再次委派 source 补读，不先退回旧版。补读保存为新版本，旧版正文、审核与验收记录不变，新版必须独立审核及总控验收。已确认制作需求保持不变；补读正在执行或新报告尚未验收时，编剧入口等待其完成。系统规则包升级为 2026-09-19.2，保留旧包及历史执行快照。

## 2026-09-19 聊天出图

数据库版本 8 新增 image_generations：保存所属项目/任务、执行与调用编号、聊天消息、提示词、参考图、状态、结果文件和产出版本。原图仍放独立文件目录，生成结果只接受原生工具返回的图片字节，不接受模型提供的磁盘路径或远程下载地址。相同执行/调用去重，同任务禁止并发出图；连接中断标为失败，不盲目重发。

出图由受限的独立 Codex 原生图片会话完成，普通业务 AI 仍只通过工作台工具发起。总控请求由系统转节点制作，再交该节点独立审核；审核和总控验收工具强制要求本轮读取对应真实图片。参考资源只接受本项目原始参考、最新已验收图片或本节点待返修图片。新版本使旧审核失效；生成记录和图片文件与产出原子关联，写入冲突回滚并清理未引用文件。聊天历史图片不继承其他新图的验收状态。

规则包 2026-09-19.3 保存到数据库，旧规则、用户配置和历史执行快照保留。视频制作与合成仍由人工处理。

## 2026-09-19 角色首样依赖

数据库版本 9 新增 image_task_specs，按任务保存单一用途及首样任务编号，补充图同时写入正式 dependencies。首样须为本剧本最新已验收人物产出且有真实图片；内部审核通过或只有文字均不足。生成时自动加入首样图参考，返回产出明确显示用途与首样名称。未通过首样、跨项目关联、自引用及更换已绑定用途会被拒绝；升级保留现有产出，不追认历史拼板。

业务工具按实际任务类型授权：分镜/编剧无 generate_image；只有资产/画面制作可实际生成，总控调用该能力时仍由系统转制作与独立审核。成员工具列表与执行权限一致。规则包升级到 2026-09-19.4，保存数据库，保留旧规则、用户自定义和执行快照。渲染器单独限制布局：单画面或仅同角色三视图；是否违反图种边界仍须视觉审核。
