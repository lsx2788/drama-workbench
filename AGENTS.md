# Drama Workbench

Read docs/方案.md before changing domain behavior. This is a local-first foundation, not an operational autonomous film studio yet.

- Overview is a read model derived from authoritative tables. Never persist duplicate current-stage fields on projects.
- Agents belong to workflow nodes. No job/role-template entity. A coordinator is attached to a coordinator node.
- Workflow creation, node setup, node AI assignment and work-item setup belong to the AI-facing APIs. Keep the workflow UI focused on inspection, navigation, discussion and user review; do not reintroduce manual setup controls.
- Present workflows as a direct panel without zoom/fit controls. Optional sections express shared preparation, repeatable episode/chapter units and final delivery. Units have independent nodes and sessions, share explicit asset versions, and extend through the units API; do not model repetition as cyclic dependency edges. Final delivery waits on every unit and cannot silently acquire new prerequisites after starting.
- The main flow is one connected vertical overview: coordinator/project information, actual shared steps, optional seasons, clickable episode/chapter entries, and archive. Opening a unit shows its own internal graph. Seasons only group existing units; overview membership/navigation links never become execution dependencies. Do not require seasons or fabricate future seasons/episodes to fill the layout.
- New projects start with an unpublished draft discussion container, a coordinator node, its unconfigured AI and one empty session. Do not auto-publish or display a flowchart during intake. The flow page stays blank until an explicitly published workflow contains production nodes; coordinator chat has its own navigation entry. Publishing represents the confirmed plan. Published workflows remain appendable through APIs; units may start empty, preparation and archive are optional until needed. Adding nodes never rewrites ordinary existing dependencies. Delivery gates are added transactionally and audited; started delivery or its started items block production expansion, and empty units cannot pass archive checks.
- Navigation begins with collapsed project folders. Each project has three entries: 总控聊天, 制作流程 and 故事资产库. Internal pages open in closable tabs keyed by project and resource identity; switching tabs preserves drafts and local page state. The flow page keeps its graph mounted. Clicking nodes, seasons or episode entries opens modal details, never a new workspace tab; node chats stay inside the node modal. Nested previews/settings/forms close back to their parent modal. Quoting to the coordinator dismisses flow modals before navigation. Existing standalone chat pages remain supported. The library opens with category folders; each folder lists and searches only its own records. Keep production records separate from creative assets, and never default to an all-records table. Aggregate without duplicating authoritative data.
- Humans message the coordinator only; child discussions are readable and quotable. Do not add fake AI replies.
- Persist agent identity, sessions, external session identifiers, configuration snapshots, messages and discussion highlights independently.
- AI prompt editing is project/agent scoped and uses expected-version checks. Save immutable prompt revisions and pin each newly submitted human message to its revision in the same transaction. Editing affects future messages, including in existing sessions, never old references. Legacy messages without snapshots remain explicitly unrecorded; migration baselines are not historical execution evidence. No runtime is connected yet; label these submitted-message configurations, not executed model inputs.
- System policies, mandatory tools/Skills and allowed capability ranges are platform-owned and cannot be changed by user configuration APIs. After migration 17, instructions contains editable content only; use the versioned prompt.layers for system rules and capability snapshots. Optional choices must stay within the AI's explicit allowed range and satisfy Skill dependencies. Clearing user content or choices must preserve system requirements. Preserve legacy unsplit versions; never fabricate historical layer bindings. New node-specific profiles require explicit node types or platform-owned node_ai_profiles bindings, not name/prompt heuristics.
- Deterministic APIs: explicit filters, standard JSON, no fallback guesses or silent relaxed matches.
- Asset variants coexist; versions revise the same asset. Published versions and their lineage are immutable.
- Store media outside Git. Never commit user media, tutorial downloads, databases, credentials or raw conversation exports.
- Story imports only persist original text/files and metadata. Content parsing belongs to downstream AI; do not decode uploads, infer encodings, extract text or generate previews during import or metadata lookup. Serve original bytes through the download API. Explicitly opened reader pages may decode TXT/Markdown bytes in the browser for display only; use an explicit encoding selection, never infer encoding or rewrite source files. Story messages carry the original-file API path, never inline story content; chat displays only the original filename as an attachment button, without the raw path or a story-source label. Clicking the filename opens a modal preview, never a new workspace tab. Keep the stored AI message path unchanged. Story uploads also accept PNG/JPG/JPEG/WebP/GIF images, stored as original bytes without OCR, conversion or analysis; explicit image preview uses a project-scoped authenticated image response, not a client blob URL. Only the on-demand preview checks PNG/JPEG/GIF/WebP signatures to set a correct inline MIME even when extensions are wrong; import and metadata remain storage-only. Fit image previews to available width, never viewport height; long images scroll vertically at readable width.
- Multi-file story imports are one atomic batch with ordered independent sources, one project and one coordinator message. Preserve batch idempotency, clean up files on rollback, and keep one ordered attachment per source without duplicating message rows. Maintain legacy single-file imports and historical chats.
- User selections and creator notes are transient coordinator-message input, never separately persisted briefs or project settings. Import accepts only source data. After import, the discussion API formats selections into one human message with a story reference; it creates no decisions or requirements. The coordinator decides how to record later conclusions. Preserve existing chats and legacy data; do not read legacy briefs as current settings.
- Preference categories/options live in the backend database with ordering, enablement and custom-input labels. Seed once; never overwrite edits on restart. The UI fetches the catalog. Validate selected categories/options against that catalog, rejecting duplicate/unknown/disabled/cross-category choices and stale hidden custom values. Discussion retries return the first saved handoff without changing its message; failures preserve the source and leave unsent choices in the current form only. An unconfigured runtime must not claim analysis has started.
- Current preparation scope is original analysis, coordinator-confirmed requirements, confirmed adaptation framework, and writer-created empty episode entries with unchanged source references. Read docs/前期流程接口.md for these contracts. Keep episode production steps undefined until discussed. Writers may delegate within their node and exchange direct parent-child messages; coordinator receives compact manifests, not copied source text. No runtime is connected.
- Preparation results/reviews and knowledge proposals/reviews are independent immutable records. Shared people/concepts/relationships become current only after coordinator review; preserve different relationship phases and explicit asset versions. Episode IDs/codes stay stable after reorder; source byte ranges require explicit encoding, page without rewriting the source. Migration 18 preserves prior messages/configurations and legacy flows.
- Hide empty library categories and unfinished library-marketplace entries; retain existing user records and working prompt/history controls.
- Core first, personal automation second, teams/skill marketplace later. Do not claim runtime execution exists before a real provider is connected.
- Run npm test, npm run typecheck, npm run build before delivery. Add meaningful tests for invariants.
