# Drama Workbench

Read docs/方案.md before changing domain behavior. This is a local-first foundation, not an operational autonomous film studio yet. OpenAI runtime contracts and current limitations are in docs/OpenAI接入.md.

Local Codex contracts are in docs/本机Codex接入.md. Separate App Server transport, session orchestration and domain tools. Never read or copy Codex auth tokens. Bind tools to the project/session server-side; disable inherited host tools, MCP and plugins. Preserve incremental thread resumption, pinned configurations, failure audits and no automatic retries. PDF/DOCX extraction into AI context is an explicit AI tool action, never part of upload or metadata lookup. Explicit user-opened DOCX previews may render on demand in the browser, without persisting extracted content or sending it to AI.

Keep developer/system context notes out of Codex user input. Give owned backend threads explicit project/agent names, archive them after terminal turns, and unarchive/resume the same thread on the next request. Never delete native history or archive unrelated desktop tasks. Running backend threads may remain visible until completion.

- Overview is a read model derived from authoritative tables. Never persist duplicate current-stage fields on projects.
- Agents belong to workflow nodes. No job/role-template entity. A coordinator is attached to a coordinator node.
- Workflow creation, node setup, node AI assignment and work-item setup belong to the AI-facing APIs. Keep the workflow UI focused on inspection, navigation, discussion and user review; do not reintroduce manual setup controls.
- Present workflows as a direct panel without zoom/fit controls. Optional sections express shared preparation, repeatable episode/chapter units and final delivery. Units have independent nodes and sessions, share explicit asset versions, and extend through the units API; do not model repetition as cyclic dependency edges. Final delivery waits on every unit and cannot silently acquire new prerequisites after starting.
- The main flow is one connected vertical overview: coordinator/project information, actual shared steps, optional seasons, clickable episode/chapter entries, and archive. Opening a unit shows its own internal graph. Seasons only group existing units; overview membership/navigation links never become execution dependencies. Do not require seasons or fabricate future seasons/episodes to fill the layout.
- New projects start with an unpublished draft discussion container, a coordinator node, its unconfigured AI and one empty session. Do not auto-publish or display a flowchart during intake. The flow page stays blank until an explicitly published workflow contains production nodes; coordinator chat has its own navigation entry. Publishing represents the confirmed plan. Published workflows remain appendable through APIs; units may start empty, preparation and archive are optional until needed. Adding nodes never rewrites ordinary existing dependencies. Delivery gates are added transactionally and audited; started delivery or its started items block production expansion, and empty units cannot pass archive checks.
- Navigation begins with collapsed project folders. Each project has three entries: 总控聊天, 制作流程 and 故事资产库. Internal pages open in closable tabs keyed by project and resource identity; switching tabs preserves drafts and local page state. The flow page keeps its graph mounted. Clicking nodes, seasons or episode entries opens modal details, never a new workspace tab; node chats stay inside the node modal. Nested previews/settings/forms close back to their parent modal. Quoting to the coordinator dismisses flow modals before navigation. Existing standalone chat pages remain supported. The library opens with category folders; each folder lists and searches only its own records. Keep production records separate from creative assets, and never default to an all-records table. Aggregate without duplicating authoritative data.
- Humans use the coordinator group: without explicit mentions deliver only to the coordinator; @ children delivers one canonical human message to the coordinator and those active descendant sessions. Do not impersonate senders or duplicate message bodies. AI-to-child messages and replies are visible in the group with verified sender/recipient/reply metadata. Group membership is independent of session lifetime: pause/rejoin preserves internal/native IDs and history. Coordinator silence is an exact hidden runtime control response, recorded separately. See docs/群聊通信.md. Direct human writes into child-only endpoints remain forbidden.
- Chat presentation uses sender/time and bold inline @mentions, with a space before message text; no separate delivery labels or routing explanation chips. Resolve mentions from saved recipient identities; do not infer delivery from prose or mutate stored messages. Hide automatic group reply previews; keep explicit user quotes and the brighter styling for replies to the user.
- Keep message footers free of prompt-version, quote and highlight actions. Quote through a right-click or touch long-press menu; scrolling cancels a pending long press, and quoting preserves the draft without sending. Member names and the member list open that specific AI's configuration, with prompt history closing back to configuration and configuration back to the member list. Preserve stored prompt snapshots and message references.
- Mentions may occur anywhere and repeat or target several members. Preserve in-place wording and punctuation; share complete-name matching between draft recipient selection and rendering, prefer longest names, exclude email-like matches, and deduplicate delivery by session ID. Removing a mention removes its recipient; do not use substring checks for routing.
- Persist agent identity, sessions, external session identifiers, configuration snapshots, messages and discussion highlights independently.
- Coordinator workflow outlines are persisted draft proposals with immutable revisions and chat cards. Reuse the graph in a modal for preview and node details; never create or publish production nodes merely to preview a proposal. Validate project scope and acyclic dependencies. Typed mentions bind to real active sessions at the caret; no separate mention toolbar button. Human messages align right, AI messages left.
- Coordinator pages keep chat mounted in the flexible center. Use a collapsible compact outline on the left and a narrow folder-only reference pane on the right; folder contents and asset/source details open nested dialogs. Full workflow graphs remain available in a preview dialog. ResizeObserver measures the available workspace, automatically collapsing sides without losing chat drafts; narrow screens show small entry buttons that open dialogs, never full-width stacked side panels. Side panels remain read models, never inferred facts or duplicate storage.
- On phones, collapse internal tabs into the topbar page picker, member chips into the members dialog, and idle connection notices into a compact status. Keep messages as the main independently scrolling region and the composer inside the visual viewport. Follow keyboard viewport resize without remounting chats, preserve drafts, use readable input sizing, and keep directory/page/member/outline/reference controls accessible through compact entries.
- Right-side references only show existing nonempty content, grouped by confirmed versus under discussion; originals are separately labeled saved sources. Keep the last confirmed baseline visible beside a newer proposal. Asset certainty belongs to a specific version: show the latest approved and newer candidate separately, and open that exact version. Omit rejected versions, superseded highlights and empty asset registrations from the current summary without deleting history.
- Both library and chat references derive from storyRecords and the same workspace snapshot. The side pane is a subset: original sources, current preparation results/highlights, shared character/scene/prop/costume/composite assets, and other assets explicitly referenced by generated-image version IDs in the current chat group. Do not mirror prompts, execution logs or unrelated media into the side pane. Hide empty knowledge panels, story-information entries and library groups; loading a preparation setup alone is not evidence that story knowledge exists. Keep all historical records in the full library.
- Specialist registration is not group participation: prepare creates/finds only the requested profile, initially available. The coordinator invites/resumes selected children through ask_child and pauses them when appropriate; never auto-join all known agents. Keep membership UI observational and retain native/internal session IDs on exit. Pass task references independently from readable chat prose. Display projections may humanize legacy technical metadata, but must not mutate canonical messages or AI context. See migration 22 and docs/群聊通信.md.
- AI prompt editing is project/agent scoped and uses expected-version checks. Save immutable prompt revisions and pin each newly submitted human message to its revision in the same transaction. Editing affects future messages, including in existing sessions, never old references. Legacy messages without snapshots remain explicitly unrecorded; migration baselines are not historical execution evidence. Submitted-message configurations differ from ai_calls actual request snapshots; only real provider responses count as executed output.
- System policies, mandatory tools/Skills and allowed capability ranges are platform-owned and cannot be changed by user configuration APIs. After migration 17, instructions contains editable content only; use the versioned prompt.layers for system rules and capability snapshots. Optional choices must stay within the AI's explicit allowed range and satisfy Skill dependencies. Clearing user content or choices must preserve system requirements. Preserve legacy unsplit versions; never fabricate historical layer bindings. New node-specific profiles require explicit node types or platform-owned node_ai_profiles bindings, not name/prompt heuristics.
- Deterministic APIs: explicit filters, standard JSON, no fallback guesses or silent relaxed matches.
- Asset variants coexist; versions revise the same asset. Published versions and their lineage are immutable.
- Store media outside Git. Never commit user media, tutorial downloads, databases, credentials or raw conversation exports.
- Sidebar projects are labeled 剧本. Deletion requires a confirmation dialog and only marks project_trash; preserve all records, files and native session IDs. Trash supports restore, never hard delete or automatic cleanup. Keep legacy archives distinct. Reject deletion during queued/running AI turns, block normal API access to trashed projects, and close their workspace tabs after deletion.
- Story imports only persist original text/files and metadata. Content parsing belongs to downstream AI; do not decode uploads, infer encodings, extract text or generate previews during import or metadata lookup. Serve original bytes through the download API. Explicitly opened reader pages may decode TXT/Markdown bytes in the browser for display only; use an explicit encoding selection, never infer encoding or rewrite source files. Story messages carry the original-file API path, never inline story content; chat displays only the original filename as an attachment button, without the raw path or a story-source label. Clicking the filename opens a modal preview, never a new workspace tab. Keep the stored AI message path unchanged. Story uploads also accept PNG/JPG/JPEG/WebP/GIF images, stored as original bytes without OCR, conversion or analysis; explicit image preview uses a project-scoped authenticated image response, not a client blob URL. Only the on-demand preview checks PNG/JPEG/GIF/WebP signatures to set a correct inline MIME even when extensions are wrong; import and metadata remain storage-only. Fit image previews to available width, never viewport height; long images scroll vertically at readable width.
- Multi-file story imports are one atomic batch with ordered independent sources, one project and one coordinator message. Preserve batch idempotency, clean up files on rollback, and keep one ordered attachment per source without duplicating message rows. Maintain legacy single-file imports and historical chats.
- DOCX reading previews load browser conversion lazily after the user opens the file. Sanitize generated HTML with an explicit reading-only allowlist; disable external document access and embedded style maps, show embedded raster images only, and keep the original download available on failure. Preserve source bytes, project-scoped file access and nested modal navigation. Reading layout is not a claim of exact Word pagination.
- User selections and creator notes are transient coordinator-message input, never separately persisted briefs or project settings. Import accepts only source data. After import, the discussion API formats selections into one human message with a story reference; it creates no decisions or requirements. The coordinator decides how to record later conclusions. Preserve existing chats and legacy data; do not read legacy briefs as current settings.
- Preference categories/options live in the backend database with ordering, enablement and custom-input labels. Seed once; never overwrite edits on restart. The UI fetches the catalog. Validate selected categories/options against that catalog, rejecting duplicate/unknown/disabled/cross-category choices and stale hidden custom values. Discussion retries return the first saved handoff without changing its message; failures preserve the source and leave unsent choices in the current form only. An unconfigured runtime must not claim analysis has started.
- Current preparation scope is original analysis, coordinator-confirmed requirements, confirmed adaptation framework, and writer-created empty episode entries with unchanged source references. Read docs/前期流程接口.md for these contracts. Keep episode production steps undefined until discussed. Writers may delegate within their node and exchange direct parent-child messages; coordinator receives compact manifests, not copied source text. OpenAI runtime can call these scoped services and directly execute child sessions with bounded calls/depth.
- Preparation results/reviews and knowledge proposals/reviews are independent immutable records. Shared people/concepts/relationships become current only after coordinator review; preserve different relationship phases and explicit asset versions. Episode IDs/codes stay stable after reorder; source byte ranges require explicit encoding, page without rewriting the source. Migration 18 preserves prior messages/configurations and legacy flows.
- Coordinator must inspect child deliverables and explicitly approve or return them with reasons and revision criteria. Chat claims never confer approval. Use pending_reviews, record/knowledge_proposal/asset and scoped review tools; children cannot self-approve. Revisions start unapproved and preserve prior reviews. Preparation usable is a derived backend field requiring a confirmed latest version and usable upstream basis; formal downstream calls enforce it. Knowledge publication requires approved linked asset versions. Migration 25 appends immutable system/config revisions without rewriting user instructions, old message bindings, approvals or session IDs.
- User confirmations are explicit chat_confirmations records, never inferred from question marks. Coordinator ask_confirmation atomically publishes one yellow message per independent question; key retries are idempotent. Clicking quotes without sending or approving. A compact count outside chat opens a list with message navigation; right swipe on phones / context menu on PC can skip only after a confirmation dialog and server confirm:true. Keep source messages and audit. Only the current group coordinator can resolve a pending question from a later real human reply. Answered/skipped never confer production approval; a quote or ambiguous reply alone does not resolve it. Migration 26 preserves historical messages/configuration/session bindings.
- Hide empty library categories and unfinished library-marketplace entries; retain existing user records and working prompt/history controls.
- Core first, personal automation second, teams/skill marketplace later. Do not claim runtime execution exists before a real provider is connected.
- OpenAI secrets stay in ignored local configuration or environment variables, never project state, browser responses, prompts or logs. Runtime writes turn/call/tool audit records separately from work-item plans. Enqueue idempotently and lock each active session; never automatically retry uncertain paid calls after failure or restart. Original attachments stay unchanged, models read on demand. Generated images become candidate assets with chat references, never auto-approved. Runtime tool identities/project scope are server-bound and profile capabilities enforced. Do not infer arbitrary Skill execution from stored Skill descriptions. Current worker requires a persistent single Node process.
- Run npm test, npm run typecheck, npm run build before delivery. Add meaningful tests for invariants.
