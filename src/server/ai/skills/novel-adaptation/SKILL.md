# 原作转整体剧本

## 输入与边界

已验收原作理解、已确认制作需求、相关原文、当前交付范围。确定本轮要框架、片段还是完整剧本，避免把框架任务扩成全本。原作事实、用户约束和改编方案分开。

## 方法

1. 提炼故事核心：谁为了什么、遭遇什么阻碍、失败会失去什么；明确观众应理解的情绪和变化。视觉短片可以是动作或意境推进，不强造复杂人物弧线。
2. 先选支撑核心因果的事件，再组织可见行动、对白与结果。压缩重复解释、合并功能相近的场景时，维护人物动机、信息获得和关键物品来路。
3. 把心理叙述转成可见可听的选择，不把所有内心活动都写成旁白；确需旁白则说明其补充的信息。具体镜头角度和运镜留给分镜 AI。
4. 以节拍或场景提纲检查结构，再按任务展开文本。三幕、节拍表等是诊断工具，不能把固定转折数、页数或“每集必须打脸”变成验收硬门槛。
5. 发现篇幅容量与用户范围冲突时，给保留核心的压缩方案及调整范围的备选，说明损失。重大变化通过 ask_node 交审核判断是否上报，系统回传后再执行。

## 交付

改编范围与版本依据 / 故事核心 / 人物目标与变化 / 事件或场景提纲 / 本轮要求的剧本文本 / 改编取舍与待确认项。问题与管理说明放在正文外。

需要具体转写时读 [戏剧化改编](references/dramatic-adaptation.md)；需要选择结构和适配题材时读 [结构与题材](references/genre-structure.md)。实际分集另用本角色的 episode-planning，不能假装已转交另一 AI 或建立节点。审核入口：[审核要点](review.md)。

正例：删去重复打听消息的两场，保留唯一获得线索的场景，使后续追查有依据。
反例：为了“爽感”让人物无故背叛，或在整体剧本里预定二十个镜头。修正：回到人物目标与已确认改编边界，镜头留到分镜。
